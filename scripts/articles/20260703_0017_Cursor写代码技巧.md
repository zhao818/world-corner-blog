技巧 1：拒绝长篇大论，善用 @ 赋予 AI“上帝视角”

很多人调教 Cursor 的方式是：复制一大段代码，扔给对话框说：“帮我重构一下。”
达辩！ 这不仅浪费 Token，还容易让 AI 丢失上下文。

正确姿势是熟练运用 @ 符号。它是你精准指挥 AI 的“瞄准镜”：

@Files：不要让 AI 瞎猜，直接把关联的配置文件、接口定义文件喂给它。

@Folders：写新功能时，直接 @src/components，让 AI 学习你现有的组件编写风格，保持代码规范一致。

@Web：遇到最新的 API 或者是尚未在 AI 知识库中的框架（比如 Next.js 的最新版本），直接 @Web 加上你的问题，Cursor 会实时联网搜索官方文档再写代码，彻底告别“幻觉”。

💡 黄金法则： 每次提问前，强迫自己想一想：我用 @ 锁定最精准的范围了吗？

技巧 2：让 AI 听懂人话的“秘密武器” —— .cursorrules

这是高手和普通人拉开差距的绝对分水岭。

在你的项目根目录下，新建一个名为 .cursorrules 的文件。这个文件就是你对这个项目的“最高法律”。你可以在里面规定：

“本项目使用 TypeScript，严格禁止使用 any。”
“所有的样式必须使用 Tailwind CSS，不要写独立的 CSS 文件。”
“提交修改时，必须严格遵守 Commitlint 规范。”

有了这个文件，Cursor 在自动生成代码或在对话框回复时，会无条件服从这些规则。你再也不用一遍遍地在对话框里纠正它：“说了不要用 any，怎么又用了？”

技巧 3：不要只在 Chat 聊天，学会用 Cmd/Ctrl + K 行内进化

很多同学遇到 Bug，习惯在左侧 Chat 窗口提问，然后再手动把代码复制粘贴回编辑器。
太慢了！ 请死死记住快捷键：Cmd + K (Mac) / Ctrl + K (Windows)。

选中一段代码 → 按下快捷键 → 输入“将这段异步请求改成 try-catch 捕获，并加上 loading 状态”。

点击 Accept，代码直接在原地被替换，红绿对比的 Diff 视图一目了然。

进阶组合拳： 在 Cmd + K 的输入框里，同样可以配合 @ 使用。比如：选中代码 + Cmd+K + "参考 @api.ts 帮我把这个方法的入参对齐"。一秒搞定。

4. 终极杀招：用 Composer (Cmd+I) 进行跨文件架构

如果说 Cmd + K 是战术攻击，那么 Composer（组合器） 就是战略核武器。

传统的 AI 助手一次只能帮你改一个文件。但现实开发中，加一个功能往往需要：修改 Router.ts → 增加 Controller.ts → 修改前端 Page.tsx。

按下 Cmd + I（或 Ctrl + I） 打开 Composer 模式：

直接用大白话下达指令：“帮我在后台管理系统里加一个‘导出 Excel’的功能。”

你会看到 Cursor 像一个真正的资深架构师一样，同时在左侧的多达 4、5 个文件中并行修改、新增代码。

检查完毕后，点击 Save All。

这一刻，你不是在写代码，你是在批阅代码。

技巧 5：善用 Tab 键的“读心术”（Predictive Edit）

Cursor 的自动补全（Copilot 模式）和其他工具最大的不同在于：它不仅能预测你当前行想写什么，还能预测你下一步想去哪里修改。

当你在一处修改了变量名，按下 Tab 补全后，不要急着敲回车。看一眼光标，Cursor 往往已经帮你预测到了下一个需要修改的文件或行数，再次按下 Tab，光标会自动“瞬移”过去并给出修改建议。

顺着它的节奏按 Tab，你会有一种和 AI 在进行“双人四手联弹”的丝滑感。

技巧 6：用 .md 文件写大需求，让 AI 按图索骥

面对一个复杂的业务大需求，在对话框里一条条发消息，很容易聊着聊着 AI 就“断片”了。

最佳实践：

在项目里建一个 todo.md。

用 Markdown 把你的需求拆解成步骤（步骤一、步骤二、步骤三）。

打开 Composer (Cmd + I)，输入：请读取 @todo.md ，严格按照里面的步骤帮我实现功能，完成一步就在 md 文件里打个勾。

这种把文档驱动开发（DDD）和 AI 结合的方式，不仅成功率极高，而且逻辑极为清晰，大项目绝不翻车。

用好 Cursor 的核心，其实是心智模型的转变。

以前我们的核心竞争力是“手速和语法熟练度”；而在 Cursor 时代，你的竞争力变成了“架构思维、问题拆解能力和 Review（审查）能力”。
