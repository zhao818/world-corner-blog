03 多Agent实战的3个“隐形大坑”

看似很爽对不对？但如果你自己去写代码落地，大概率会遇到以下三个“鬼故事”：

1. 无限循环套娃（死锁）

现象：程序员写的代码有Bug，测试指出Bug；程序员改了之后引入了新Bug，测试继续指出……两个Agent在控制台里疯狂对话，10分钟烧掉了你几百美刀的Token。

解法：必须在框架层引入 Maximum Rounds（最大轮次限制） 或者 人类介入机制（Human-in-the-loop）。当对线超过5轮，强制弹窗让人类评判。

2. “传话筒”导致的语义断崖

现象：产品经理写了1000字的需求，传到架构师剩500字，传到程序员手里只剩一句话：“写个贪吃蛇”。

解法：建立 共享记忆库（Shared Memory） 或 全局黑板机制（Blackboard Architecture）。所有Agent不仅能接收上家的信息，还能随时查阅最初的、最完整的全局上下文。

3. 人设崩塌

现象：测试Agent聊着聊着，突然开始帮程序员写代码；或者程序员跳起来去改产品需求。

解法：在 System Prompt 中使用强约束。例如：“You are a STRICT QA. DO NOT write any functional code. You ONLY output test results and bug descriptions.”
