## 症状
> 你看到什么？

和 AI 协作做了一整套书籍架构规划（章节设计、字数分配、主题方向），会话正常结束。下次开工发现：规划文件没 commit，本地修改丢了（或被覆盖）。全部重来。

## 根因
> 真正的原因是什么？

人的注意力在"思考规划内容"上，不在"保存规划结果"上。规划过程可能持续几十分钟到几小时，期间一直在输出和修改，但 `git commit` 不在意识里。会话结束时，要么忘了 commit，要么会话异常退出导致未保存的修改丢失。

**本质：规划和保存是两个独立动作，大脑把"想完了"误认为"存好了"。**

## 修复
> 具体怎么修的？

建立纪律：**规划完成一个阶段 → 立刻 commit，10 秒的事。**

```bash
# 不要等到"全部做完"，每完成一个可独立交付的片段就：
git add projects/xxx.md
git commit -m "docs: xxx 架构初版完成——章节+字数分配"
```

具体到 AI 协作场景：让 AI 在每次完成阶段性规划后主动 commit，不等人提醒。

## 怎么避免
> 下次怎么不踩？

- **铁律：规划做完立刻存仓库，不等会话结束**（已写入 `~/claude-memory/global/feedback/plan-must-commit-immediately.md`）
- AI 协作时，要求 AI 主动 commit，不允许"等会话结束时再存"
- 每完成一个可独立交付的片段就 commit，把 commit 当保存键用
